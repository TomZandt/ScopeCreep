# Changelog

All notable changes to scopecreep are documented here.

The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning 2.0.0](https://semver.org/). See [CONTRIBUTING.md](CONTRIBUTING.md) for how versions and entries are decided.

## [Unreleased]

### Added
- The Update dialog (#246, spec #234): when the start-up check finds a newer Release, once the Window is up a dialog centred over it says "ScopeCreep X.Y.Z is available (you have A.B.C)" with a What's new link to the Release's page and three buttons. Update opens the Release's page (on every platform for now), Skip this version remembers it until a newer one appears, and Later, Escape or a click outside close it until the next start. Help's "Update to X.Y.Z…" entry opens the same dialog, and it is never shown when up to date or when the start-up check is off. The Feed carries on behind it.
- The Update check (#245, spec #234): at start-up the app asks GitHub's Releases list, once and in the background, whether a newer Release has an Installer for this platform (newest Semantic Version, so 0.10.0 is above 0.9.0; drafts and Test builds ignored). If so, Help's Check for updates entry reads "Update to X.Y.Z…" and opens that Release's page. Settings, "Check for updates at start-up" (on by default, remembered) turns the start-up check off; the Help entry then checks on demand and opens the Release page, or the Releases page when nothing is newer. The check gives up after 5 seconds, sends only the User-Agent "ScopeCreep/X.Y.Z", and says nothing when it fails. This is the one time the app goes online by itself.
- A Help menu, last on the Menu bar after Settings (#231, spec #230): Licence…, Changelog…, Website, Report a problem…, Check for updates and Buy Me a Coffee… each open the right page in the system browser (Report a problem opens a new GitHub issue with the version and Feed protocol filled in). The Hotkeys panel, now long, flows into a second column when it passes the menu height cap, so the Window's least size is 1420 × 764 (was 833). Each is a Command with no default Hotkey (`help-*`), so it can be given one in the Hotkeys panel. The app itself never goes online; a failure to open the browser only logs.
- An About popover: Help, then About ScopeCreep… (first in the menu) opens a card centred in the Window with the ScopeCreep wordmark, the version and Feed protocol (as `--version` prints them after the name, which the wordmark is), "by Tom Zandt-Valentine", the © and licence line, and Website, Licence and Buy Me a Coffee links. It closes on Escape, a click outside or its close control (#232, spec #230). A Command (`help-about`) with no default Hotkey.

## [0.4.0] - 2026-11-25

### Added
- Pushing a `vX.Y.Z` tag publishes the Release (#243, spec #233): the `release` workflow builds the Installer for each platform in `packaging/platforms.txt` and a `publish` job makes a GitHub pre-release (while 0.y.z) named by its version, with that version's changelog section, a Full changelog link, the platforms included, each Installer and `SHA256SUMS`. It refuses a tag that does not match the workspace version or has no changelog section (`scripts/check-release-tag.sh`). The README has a Download section pointing at the Releases page.
- The Linux Installer and its scripts (#241, spec #233): `scripts/package-linux.sh` makes `scopecreep-X.Y.Z-linux-x86_64.tar.gz` (the app, the Sender bundle, `install.sh` and `INSTALL.txt`) and `SHA256SUMS`; `install.sh` installs and uninstalls the app (`~/.local/bin` or `/usr/local/bin`) and the Sender (`/usr/OFX/Plugins`, saying it needs admin rights and to restart Resolve); `scripts/release-notes.sh` prints a version's changelog section and a Full changelog link.
- The Window's text is now set in the brand fonts, bundled with the app (no system fonts; ADR 0045, #238): DM Mono (Regular, with Medium for the focused Panel's name and headings) for every label, value, menu, tag, tooltip and number, so every digit has the same width and numbers no longer shift, and Anton for the wordmark in the Stylesheet (the About popover will use it when it is built). The symbols the UI draws (the value box's arrows, reset, the edge +, the settings button's dots) are now Lucide icons from a bundled, subset icon font through one `Icon` enum (ADR 0046). The fonts and icons keep their licences (SIL Open Font Licence for the fonts, ISC and MIT for Lucide), listed in the new THIRD-PARTY.md with their sources in `app/assets/fonts/README.md`. The text takes no more room than the layout already reserved, so the least sizes do not change: a Panel is at least 255 wide and the Window at least 1420 × 833.
- The brand accent (#d2ff00, a lime) and the Hairline look (ADR 0044, #226): the chrome stays grey and the accent is only thin lines and text. A chip that is on is accent text with a 2 px line at its foot, the page tab and tab group tabs are accent text and underline, the focused Panel has an accent line along its title bar (no frame round the picture), sliders have a thin accent track with a grey thumb, a hovered menu row has an accent bar and a chosen one a small square, and the dock overlay is a dashed accent outline with a label ("Split left", "Join as a tab", "No room to split: join as a tab", "Swap places"). Hover is a neutral lift, never the accent. Settings > Appearance sets the App accent colour (swatches, a hex box, Reset, and a notice when the contrast is under 4.5:1) and remembers it in its own file.
- Spacing and readability follow the interactive demo: taller bars and rows (menu bar 32, page bar 36, title bar 34, chips 24), text 13 with a floor of 12, a lighter text colour for tags and scale numbers, and 8 px between Panels.
- When a title bar is too narrow for its chips, a "+N" chip stands for the ones that gave way and opens the Panel's settings, where they are; the view block (Fit, readout, Link) is only on picture Panels, never on a scope, and the rule before it only where the Panel has chips.
- Settings, Reset all Panels to defaults… puts every Panel's settings, on every page, back to its display's defaults, after a confirm row ("Reset all Panels to defaults? Settings of every Panel on every page go back to default", Cancel first, then Reset). It is also a Command (`panels-reset-all`, no default hotkey) in the Hotkeys panel. Arrangement, zoom, Link, pages and tabs are not touched. The Hotkeys panel's extra row makes the Window's least height 669 (was 645) (#228).
- The glossary defines Installer, Release, Test build and Update check, for the coming downloads for Linux, Windows (NVIDIA) and macOS (Apple Silicon) and the app's check for a newer Release at start-up (ADR 0043 records where the Feed lives on each platform).
- The glossary calls the page that shows every UI component in every state the Stylesheet (it was the style showcase).
- Fit, the zoom readout and Link are back on every Panel's title bar as one block at the top right, after a divider from the Panel's own chips and before the settings button; the view strip in the menu bar row is gone. The scopes have the block too, greyed where nothing zooms, so it is always in the same place. Fit takes that Panel (and every picture Panel while Link is on) to Fit; Link stays one Window-wide switch, on in a first session. A Panel's least width is now 176 (was 120) so the block fits, which makes the Window's least size 1015 × 645 (#224, ADR 0042).
- The Colour Setup line is now at the right end of the menu bar row, so the full-width row under the menu bar is gone and the Panels have its height back. It is cut with an ellipsis before it can meet the menus, and hovering it shows the whole line (#224, ADR 0042).
- Right-click on a page tab opens the Layout menu's entries (go to the page, New page from, Duplicate, Rename, Delete, Add panel, Auto layout, Auto resize, Undo, Default layout) from the tab, after making that page the current one. The Layout menu in the menu bar stays (#224, ADR 0042).
- The app is called ScopeCreep in the README, the glossary, the research notes, the Feed protocol, the window title, `--version` and the notices it shows.
- A Panel's settings popover is easier to use (#225). Every amount is one row like Resolve's own: label, slider, a **value box** you can type into (with up and down arrows; Up and Down keys, Shift for ten steps, Enter accepts, Escape cancels; clamped to the slider's range, in its unit), and a small circular **reset** arrow that goes back to the default (its tooltip names it, "Reset to 100 %", and it is dim at the default). The "Reset to default" text line is gone. The popover's Panel section has a **reset this Panel's settings** icon in its corner that puts every setting of that Panel back to default in one step (its position, size, zoom and tab stay); it is dim when all is at default. The popover is wider and roomier: groups are apart, with a heading and a line each, taller rows and bigger hit targets, and the Panel section set well apart at the bottom.
- A Sponsor button on the GitHub repository and a line in the README that link to buymeacoffee.com/tomzandtvalentine.
- Gamut Warning, Neutrals and Chromaticity are back in the Window (the former gamut/legal warning, Highlight Neutrals and CIE plot, renamed). Add panel, a Panel's edge **+** and Replace with list them A to Z with the other seven; they are not in the default layout or the page templates, so a page gets one by adding it. Each can be duplicated and closed like any Panel, keeps its own settings, and costs nothing while it is not on the page you are on. Pages and settings saved under the old names still load (#222).
- A **Displays** table in the glossary: the seven displays in the Window with their kind, purpose and former name, and the six kept out of the Window.
- A regression test that a freshly started Window and the Feed thread keep going while Panels are made, hidden, drawn and removed (`display_lock_stress`).
- Page templates. The **+** menu's New page from now also offers All 7 Panels, Picture views (clean picture, ARRI False Colour, Stops False Colour, Saturation heatmap, Skin tone), Scopes (clean picture, luma waveform, Vectorscope) and Picture only. Each page is named after its template (rename it as any page), has its own Panels and settings, is remembered like any page, and is arranged once with Auto layout for the footage on screen (16:9 with no Feed); if the Window is too small for that, the Panels are simply halved (#215, ADR 0041).
- Auto layout re-roll. Pressing Auto layout again shows the next-best arrangement of the page (the best 8, then back to the best), so you can step through variations; each press is one undo step, so Undo goes back through them. Any other change to the page, or new footage aspect, starts again at the best. Above 9 Panels there is only one arrangement, so a repeat press changes nothing (ADR 0041).
- Auto layout. A button on the Page bar (also Layout, Auto layout, and the Command "Page: auto layout", no default hotkey) re-arranges the current page once for the footage and the Window: it keeps the Panels in reading order (a tab group stays one item), tries the ways of cutting them into splits, sizes each from how much the displays matter (the clean picture most, then the luma waveform and the Vectorscope), fits picture cells to the footage, drops any cut that would leave a Panel under its least size and keeps the one that gives the most useful area. With no cut that fits, the page stays as it was and the Window names the least Panel size; above 9 Panels it just halves the list. It never runs by itself, and it is one undo step (#214, ADR 0041).
- Auto resize. A button on the Page bar (also Layout, Auto resize, and the Command "Page: auto resize", no default hotkey) resizes the current page's splits once so that picture cells fit the footage: where a split has one picture-shaped side (a Picture View or the luma waveform) its ratio is set so that Panel's picture has the Feed frame's aspect, leaving room for the title bar, the legend strip and the waveform's scale gutter, never under 15 % or over 85 %. No Panel changes place and the nesting stays; with no Feed it uses 16:9. It never runs by itself, so new footage or a new Window size leaves your layout alone, and it is one undo step (#213, ADR 0041).
- Pages. A Page bar sits under the Colour Setup line with a tab for each page ("[1] Main", "[2] Pictures": the number is the tab's position, so Ctrl+1 to 9 go to it, and there are at most nine pages). Click a tab to go to it, click it twice to rename it in place, and use **+** at the end for New page from: Empty page, Default layout (the 7 Panels) or Copy of this page (a copy gets its own Panels with a copy of each one's settings). Each page keeps its own layout, focus and undo, and the pages and the one you were on are remembered. Only the current page's Panels measure and draw, so a page you are not on costs nothing. The Layout menu lists the pages, New page from, Duplicate, Rename and Delete page (one page always stays), Add panel, Undo layout change and Default layout; Add panel is also at the right of the Page bar. On the first run your arrangement becomes the first page, Main, and each of your nine named layouts becomes a page after it, named as it was (one that cannot be read is dropped). Ctrl+Shift+1 to 9 (save into a slot) are gone; Copies saved on a page ("Clean picture 2") come back at start-up. At most 12 pages (#212, ADR 0041).
- Tab groups. Drag a Panel's title and let go in the middle of another Panel (the outline says "Tab here"): it becomes a tab there, and the title bar shows a tab for each Panel with the shown one highlighted. Click a tab to show that Panel, drag a tab out to dock it elsewhere (the others stay), and close a tab from its Panel's popover. A Panel in a tab that is not shown is not measured or drawn, so it costs nothing and keeps its settings; this also stops closed Panels measuring. When there is no room for Add panel, a **+** edge add or a side dock, the Panel now joins the focused (or target) tab group as a new tab and the Window says so and names the least Panel size, instead of refusing; each is one undo step. When the tabs do not all fit, the shown tab stays and a "+N" chip counts the rest (click it for the next). A Duplicate with no room still refuses (#211, ADR 0038).
- Undo layout change: Ctrl+Z (or Layout, Undo layout change, greyed when there is nothing to undo) steps back through the last 20 layout changes: add, close, swap, a divider drag (one step however far you drag), and showing the default or a saved layout. It never touches a Panel's settings or zoom, and it starts empty each session. Reassign it in the Hotkeys panel (#207, ADR 0038).
- Dock by dragging a Panel's title: after a few pixels of movement, let go over the outer quarter of another Panel's edge and the dragged Panel takes that half of it (the outline shows the exact half first), its old space going to its neighbour. Escape cancels, a drop on itself does nothing, and Shift on drop swaps the two Panels as before. If a side dock would leave a Panel under its least size the Window says so and names it until joining as a tab arrives (#210, ADR 0038).
- A **+** on each edge of a Panel while the pointer is over it (quiet, under the title bar and clear of the gaps). Click one to list the displays: the one you pick opens on that side at half the space and takes the focus. It is the same operation as Add panel with a chosen side, with the same list; with no room on that side the Window says so and names the least Panel size (120 × 105; 176 × 105 since #224) and the layout stays as it was (#209, ADR 0038).
- Copies of a display. A Panel's popover now has a Panel section with Replace with… (pick a display: the Panel keeps its place and size and starts on that display's defaults), Duplicate right and Duplicate below (a new Panel of the same display takes half of the cell and starts with a copy of the Panel's settings), then Close. Copies are titled "Clean picture 2", "Vectorscope 3" and so on: the number is given when the copy is made and stays with it however the Panels are moved. Two clean pictures can show different channels, zoom and Link reach every picture Panel, and closing a Panel forgets its settings so it starts fresh if it comes back. A duplicate with no room says so, as Add panel does (#208, ADR 0039).
- Add panel and Close. The Layout menu has "Add panel…" (the list of displays: pick one and it splits the focused Panel in half, to its right when it is wider than tall and below otherwise, and takes the focus) and "Close panel". A Panel's settings button now ends its popover with Close, and its neighbour takes the space. Click any Panel to focus it (a quiet outline). With every Panel closed the page shows one large Add panel button. If there is not enough room the Window says so and names the least size of a Panel (120 × 105). Add panel and Close are in the Hotkeys panel with no default hotkey, and the layout is remembered after each change; a display already on the page is greyed in the list until it can be copied (#206, ADR 0038).
- (Replaced by the view block on every Panel, #224.) A view strip at the right end of the menu bar row: Fit (takes every picture Panel to Fit), the zoom readout (the shared zoom while Link is on, "Fit" or "200 %", and "Mixed" when Link is off and the Panels differ) and Link. It is always in the same place, greyed while no picture Panel is shown, and the Window's minimum width counts it. Link keeps its saved choice and is on in a first session; the wheel, middle-drag and Z work as before (#205, ADR 0040).
- The luma and Colour Waveforms' settings have Low and High reference level sliders: two quiet dashed lines across the plot to mark a floor and a peak, such as a delivery's maximum nits. Off by default, set in the Panel's scale unit (nits on a PQ or HLG output, percent or 10-bit codes otherwise), Low can't go above High, and the lines follow the graticule brightness. One pair per Panel: a 1000 nit line stays on 1000 nits whether the scale reads nits, codes or percent, and the sliders read in the scale's unit, so where nits are not available (no PQ or HLG output) they read codes like the scale, and the nits come back with the output. Drawing only: no count changes (#128).
- Vectorscope: a Graticule choice in its popover, Standard (as before) or Hue vectors, which adds a quiet grey spoke from the middle to each of the six colour targets on both plots, so you can see how far a colour has drifted off its hue line. It follows Graticule brightness and is remembered per Panel; the trace, clipping marks and skin-tone line are unchanged (#130).
- A View menu on the menu bar, between Layout and Settings. Its first entry, "Show legends", shows or hides the legend strips of ARRI False Colour, Stops False Colour and the saturation heatmap at once (marked while all are on); each Panel's own Legend setting still works afterwards. It is "Legends: show / hide" in the Hotkeys panel, with no default hotkey (#191).
- When GPU memory runs out, the Window says so in one sentence: which side ran short (the Sender in Resolve, or the app's picture or scopes), about how much it needs, and to close another GPU app. Resolve is never affected (the Sender passes the picture through and tries again every few seconds), and the app shows the last picture and carries on by itself with the next frame once memory frees up (#35).
- `feed-synth --out-of-range`: the bottom of the moving test card becomes a grey ramp from -0.25 to 1.25, so the luma waveform's edge rows can be seen lit without Resolve (#32).

Donations and payments go through Buy Me a Coffee.
- The Sender is now called **ScopeCreep** in Resolve's OpenFX list (label and group; it was "scopecreep Sender"), and the development-only entry that stood in for the Stage 0 probe is gone. The plugin identifier is unchanged, so projects that already use the Sender still load it. The `scopecreep-test-*` projects need ScopeCreep put on their `sender` node once (README, "Test projects") (#223).
- The default layout is the owner's new arrangement: the Channel Viewer a little narrower, the scopes at its right taller for the Vectorscope and Saturation, and the bottom strip now reads False Colour - Stops, False Colour - Arri, Skin Tone. The Window's least size becomes 713 × 645 (since #224: 1015 × 645).
- The displays have new names: Clean picture is **Channel Viewer**, Luma waveform is **Waveform**, ARRI False Colour is **False Colour - Arri**, Stops False Colour is **False Colour - Stops**, Skin tone is **Skin Tone** and Saturation heatmap is **Saturation** (Vectorscope is unchanged). Panel titles, the menus, notices and the docs use them. Everything you saved under the old names is still read (settings, the Loupe and Link state, pages, named layouts, copies like "Clean picture 2") and is written under the new names from the next save on. The Add panel list, the edge **+** list and Replace with… list the displays A to Z, each once.
- The default layout is now one arrangement, the same for any footage: the Channel Viewer big at the left, the Vectorscope beside Saturation with the Waveform under them at its right, and False Colour - Stops, False Colour - Arri and Skin Tone along the bottom. It is the first page of a fresh Window, "Default layout", a Default layout new page, and what a missing or unreadable saved layout falls back to. The Window's least size is now 713 × 645 (since #224: 1015 × 645).
- The view strip's readout always says the zoom as a percentage ("62 %", "200 %"), and "Mixed" when Link is off and the picture Panels differ; "Fit" is only the button (ADR 0040).
- A Panel's title shows an instance number ("Waveform 2") only where the page holds two or more Panels of that display; one Panel of a display is just its name.
- A picture Panel's title bar no longer has a zoom chip or a Link chip: it shows its zoom as a read-only tag beside its other tags ("Fit 17 %"), and the view strip sets it. The chips of every title bar are set apart by setting, with a wider gap between groups than within one (the Vectorscope's eight chips are plots, mono and tonal range), and on a narrow Panel only the chips give way to the settings button's popover (#205, ADR 0040).
- The Window's Panels now sit in a layout tree instead of a grid (ADR 0038). It looks and works as before: same default layout, drag a gap to resize, drag a title to swap, Ctrl+F to fill the Window. Dragging a gap now moves only the two sides of that split, so a border no longer runs on across the whole Window. Saved layouts and named layouts from before still open (an old arrangement converts when it is a sequence of cuts, otherwise the default layout is used). The smallest the Window can be is now 469 × 669 (was 469 × 645), because the tree's shares need a little more height in the default layout (#204).
- The Window can't be made smaller than 713 × 645 (logical pixels; 1015 × 645 since #224; 1420 × 833 since #226, a Panel is at least 255 wide), and it now opens at 1440 × 840: the size at which every Panel of the default layout keeps its minimum size and every menu, including the Hotkeys panel, fits under the menu bar. A layout you dragged can still shrink its Panels below their minimum in a Window smaller than the one it was arranged in (#172).

### Fixed
- The settings popover matches the demo (#237): a quiet line and air before the amounts as before each group, a value box wide enough for "1023 codes", and the value box's up and down arrows (now side by side, 22 x 32) and the reset icon now clear Lucide icons (ADR 0046, #238), bright at rest and lit under the pointer, instead of tiny font glyphs.
- Dragging a slider in a Panel's popover now moves the slider and its number as you drag. The Panel's setting was already changing on each move, but the popover kept drawing the value it was opened with, so the thumb and the readout stood still (the thumb only caught up after the popover was opened again) (#225).
- The Colour Setup line under the menu bar was an empty bar: its text was drawn below its own background. It now shows the Timeline, Output, Levels and where it came from (#217).
- The Page bar's **+** and Add panel menus, an edge **+** and the empty page's Add panel button now open their list under the button that was clicked, or above it when there is no room below, not at the top left of the Window.
- Main and every other page now start on Panels of their own, Main on the first instances, so Main's saved settings apply to it and no page shows "Clean picture 2" for a single Panel; instances no page holds are removed at start-up.
- The Add list no longer lists the same display again for every copy, nor copies no page holds.
- The Window no longer waits on the Feed thread each time it draws: telling the displays which Panels are shown takes a write lock only when that changed.
- Undo after closing or replacing a copied Panel ("Clean picture 2") now brings the copy back, and Layout, Undo layout change is greyed only when nothing is left to undo; a copy is kept until no undo step names it. Closing or replacing a Panel that another page still shows keeps its settings for that page; Duplicate on a Panel that cannot be copied says so instead of "No room"; Auto resize never leaves a Panel under its least size; and a new page past the 12-page limit is refused before it makes any Panel (spec #196 review).
- The luma waveform's "> 1023" and "< 0" edge-row labels (and their percent and nits forms) are drawn whole instead of being cut by the title bar and the Panel's border, at every display scale (#183).
- A Panel arrangement saved with a border dragged close to its minimum in a large Window, or a layout saved that way, came back as the default layout at the next start. It now comes back as arranged: a column or row too small for the default Window is widened to its minimum there and the others give way (#179, ADR 0012).
- A narrow Panel's chips no longer run past its title bar. Chips that don't fit leave the bar from the right, a whole setting at a time (the zoom chip stays longest), and its settings button opens a popover that offers them first, Link included. On the clean picture at its smallest only the zoom chip stays; all of Y R G B and L show from 192 px wide (#171).
- ACES 2.0 to Rec.2100 ST2084 (1000 nit): a few dark, saturated colours were converted up to half a 10-bit code away from the ACES maths, just outside what "exact for ACES 2.0" allows; every colour of a dense test grid is now inside. The ACES 2.0 conversion takes about 1.4 ms more GPU time per UHD frame (#44).

### Known limitations
- Installers are for Linux (NVIDIA, CUDA) only; Windows and macOS follow. Builds are unsigned.
- GPU processing in Resolve must be CUDA.

## [0.3.1] - 2026-11-20

A menu bar and hotkeys you can change: the Layout menu replaces the right-click on the status line, Settings holds the Hotkeys panel, Z toggles a picture Panel between Fit and its last zoom, and Ctrl+F lets one Panel fill the Window.

### Added
- A thin menu bar across the very top of the Window, above the Colour Setup line. Its Layout menu lists Default layout and the nine layout slots by name (empty ones say so, and the layout on screen is marked): click a saved one to show it, or an empty one to save the arrangement on screen into it. "Save current layout into…" lists the slots to save into (a saved one keeps its name) and "Rename layout…" the saved ones to rename, typed into the row. Each entry shows its hotkey. Menus open on a click, follow the pointer along the bar while open, and close on a second click, a click elsewhere or Escape. The Panels lose the bar's height (#147).
- Settings, then Hotkeys…: every command with its hotkey. Click one and press the combination you want; Escape cancels, Backspace or Delete clears it. A combination another command has names that command and offers Replace or Cancel; Escape, Enter, Backspace and Delete are kept by the app. A command can be reset to its default while it is chosen, and every command from "Reset all to defaults". The menus show a change at once, and it is remembered in `~/.config/scopecreep/hotkeys` (#148, ADR 0036).
- Picture Panels: Z toggles the picture Panel under the pointer between Fit and the zoom and spot it was at, like Resolve's Shift+Z (every picture Panel while Link is on; over a Scope it does nothing). It is "Zoom: Fit / last zoom" in the Hotkeys panel, so it can be changed or cleared. The last zoom is not saved, like zoom itself (#169, ADR 0035).
- Ctrl+F makes the Panel under the pointer fill the Window (the menu bar, Colour Setup line and status line stay); Ctrl+F again or Escape puts the grid back, and so does showing a layout. Its chips, popover, zoom and Loupe work as usual; borders and title bars can't be dragged meanwhile. It is "Panel: fill the Window" in the Hotkeys panel, so it can be changed or cleared, and it is never saved (#180).

### Changed
- Layouts: Ctrl+1 to 9 (show a layout) and Ctrl+Shift+1 to 9 (save one) are now hotkeys of named commands, and behave as before. Changed hotkeys are kept in `~/.config/scopecreep/hotkeys` beside the layouts; a line the app can't read keeps that command's default, and two commands never share a hotkey (#146, ADR 0036).

### Removed
- The layout menu on a right-click of the status line, with its Shift-click and right-click and its hint line: the Layout menu on the menu bar does all of it (#147).

### Known limitations

- Ctrl+F has not been checked at the app yet (#181).
- A saved Panel grid dragged to the minimum in a window much taller than the default can be refused at the next start, giving the default layout (#179).
- The Window has no minimum size, so a very short Window cuts off the foot of a menu (#172).
- What alpha reaches the Sender from Resolve has not been checked (#156).
- Performance: the UHD 50 check passed on this build (Resolve at 50 fps throughout, the Sender at 49.99 renders a second, the app read 3,775 frames with no gap).

## [0.3.0] - 2026-11-20

Milestone 3 so far: a colourist's Window. The Window is 7 Panels with the clean picture as the hero, named layouts, Panel toolbars and sliders, zoom and pan with Link, and a joined 100 % and 200 % Vectorscope. Milestone 3 is not finished (see [#113](https://github.com/TomZandt/ScopeCreep/issues/113)); this is a checkpoint.

### Added
- Clean picture: it zooms like Resolve's Viewer. The scroll wheel over it zooms toward the pointer from Fit to 400 % of source pixels, free below 100 %, landing on 100 %, then whole steps (200, 300, 400 %), so above 100 % every picture pixel is an exact square. ### Added

- Output Conversion: when the Feed is in the Timeline Colour Space, the app converts it to the Output Colour Space on the GPU with published maths, and the Picture View and the waveform show the converted picture. DaVinci Wide Gamut / Intermediate to Rec.709 Gamma 2.4, P3-D65 (gamma 2.6) and Rec.2100 ST2084, and ACEScct (ACES 2.0) to Rec.709 BT.1886, P3-D65 and Rec.2100 ST2084 (1000 nit), are labelled "Output Conversion exact" ("exact for ACES 2.0" while the ACES version is assumed). A Colour Setup read after playback stops converts the picture already on screen (#17).
- Approximated conversions say why: DWG/DI to Rec.2020 Gamma 2.4 (not yet measured against Resolve), DaVinci tone mapping or gamut mapping on (not applied, unpublished), YRGB with colour spaces other than Rec.709 Gamma 2.4 (#17).
- Accuracy suite on the real Feed: `harness.py feed-frames` captures each test project's frames after the app's own Output Conversion, and `cargo run -p scopecreep-accuracy -- feed` compares them with Resolve's renders and checks the app's label never claims more than was measured (#17).
- Feed protocol v1.0 (`feed/PROTOCOL.md`): the versioned shared-memory hand-over between the Sender and the app, with drop counting, a reader-present flag and version-mismatch reporting. C header for the Sender, Rust crate for the app (#14).
- scopecreep Sender (`sender/`): OFX plugin on Resolve's CUDA path that copies each Viewer Frame into the Feed without ever making Resolve wait, and does no work when no app is attached (#14).
- scopecreep app (`app/`): one window with a Picture View of the clean picture, a quiet label and one-line notices; Viewer Frames chosen by pacing so background cache renders are ignored (#14).
- `feed-synth`, a synthetic Feed writer for testing without Resolve (#14).
- Luma waveform beside the Picture View (two panels): computed on the GPU from every pixel of every Viewer Frame at full resolution in 32-bit float, one waveform column per picture column, on a 10-bit scale (0–1023) with legal reference lines at 64 and 940. Pixels below 0 or above 1023 are counted and shown in their own edge rows, never cut off. A quiet label states the scale, the Measured Space and the luma weights (#15).
- Luma weights derived from the Measured Space's primaries and white point (default), or a Match Resolve mode with the weights Resolve's own waveform uses (`--luma match-resolve`) (#15).
- The Colour Setup travels with the Feed: the app shows it in the Picture View label, e.g. "ACEScct → Rec.709 BT.1886 (from project, assumes ACES 2.0)". It is read from the Resolve project through a scripting helper the app runs under Resolve's own Python (Studio, external scripting set to Local), only while playback is stopped; a changed project setting shows within a few seconds, with nothing restarted. Resolve's "P3-D65" is labelled gamma 2.6. ACES setups say "assumes ACES 2.0" (the version is not readable by script) (#16).
- Manual Colour Setup on the Sender node ("Set Colour Setup manually": Timeline Colour Space, Output Colour Space, Levels, ACES version). It wins over the project's and is labelled "set manually"; it is the way to use scopecreep with Resolve's free version (#16).
- The waveform measures in the Colour Setup's Output Colour Space when it is known (#16).
- When the Colour Setup cannot be read, the label says it is unknown and a notice says how to fix it (external scripting, or the Sender node) (#16).
- The app knows the Resolve project and timeline names (from scripting) for the Sender's identity (#16).
- `--no-scripting`: never read the project by Resolve scripting (#16).
- The waveform follows the project's Levels: with video levels black (0.0) is at code 64 and white (1.0) at 940, with data (full) levels at 0 and 1023. Its label shows the active range ("Legal 64–940" or "Full 0–1023"), followed by "set manually" when the Levels come from the Sender node's manual Colour Setup, or "assumed" (video levels, Resolve's default) while the Colour Setup is not known. The reference lines and scale numbers follow the Levels (#18).
- To compare with Resolve's own waveform on a video-levels project, turn on Video Level Scopes in Resolve's scope options (Resolve's scopes show data levels by default, whatever the project's Levels) (#18).
- `measure_feed` development example: measures live Feed frames with the app's own waveform and prints the codes of chosen columns (#18).
- A quiet status line under the panels: Resolve's live playback rate, measured from the Sender's own render times (within ±0.01 fps of the timeline rate at 24, 25 and 50 fps in Resolve; "paused" when stopped), dropped frames split into "app too slow" and "Sender busy", and the Sender driving the Feed with its project and timeline names when known (#19).
- More than one Sender: exactly one drives the Feed. Senders rendering the same frames are settled by a fixed rule (the instance Resolve created first in its process) and the others are named in a notice; a timeline switch simply follows the Sender now rendering. A second Resolve process joins the Feed as a guest, sends no frames and is flagged; it takes the Feed over when the first Resolve quits (#19).
- `SCOPECREEP_FRAME_LOG=<file>`: a per-frame timing log of what the app read and showed, for diagnostics (#19).
- The Sender node greys out its manual Colour Setup controls (Timeline Colour Space, Output Colour Space, Levels, ACES version) while "Set Colour Setup manually" is off, so it never offers settings that are not in effect; scopecreep then uses the project's Colour Setup, as before. Values set by hand are kept when the switch is turned off and come back when it is turned on again (#46).

### Changed

- The waveform takes the picture's shape: the Picture View and the waveform are the same size, in the Feed frame's aspect ratio (16:9, 2.39:1, 4:3, 9:16...), each letterboxed in its half of the window, so each picture column sits level with its trace. They follow a change of timeline resolution without a restart, and each panel's label sits directly under it (#42).
- The waveform scale's numbers keep their full gutter in a small window; on a short waveform, numbers that would overlap are left out (black and white stay longest) (#42).
- The Picture View label states the Output Conversion and how far it can be trusted, instead of "as sent, no Output Conversion" (#17).
- Feed protocol 1.2: a Sender registry in the header (instances, timeline rate, host, last render) and guest Senders from a second Resolve process. Older readers and writers stay compatible (#19).
- Background cache fills while paused are now recognised at 50 and 60 fps too (they render about 1.6-2x real time, in pairs, from two threads), so the Scopes stay on the viewer frame; a ragged playback start is held back for a moment and then shown (#19).
- Feed protocol 1.1: the slot's Colour Setup block now has a format (provenance plus `key=value` lines). It carries the Sender's manual override; 1.0 readers and writers stay compatible (#16).
- Feed frames go to the GPU once, through reused staging buffers, for the Picture View and the waveform to share: the app now keeps up with UHD float at 60 fps (#15).

### Fixed

- A Colour Setup set by hand on the Sender node no longer claims "Output Conversion exact": it cannot say whether tone or gamut mapping is on, so the label reads "Output Conversion approximated: assumes tone and gamut mapping off" (#17).
- When the Feed is shown as sent (no Output Conversion), the waveform label says "Rec.709 assumed, measured as sent, unconverted" instead of reading like a Rec.709 measurement (#17).
- The Sender no longer allocates graphics memory, pins the Feed's memory or scans Feed files on Resolve's render thread: the ring (when the first frame arrives or the frame size grows) and a second Resolve's look at the first one's Feed are handled by the Sender's own worker thread. The frame that triggers a new ring passes through and is counted as dropped ("Sender busy"); retired rings are freed by the worker even when no more renders arrive (#2).

### Known limitations

- Rec.2100 HLG, P3-DCI and sRGB outputs, ACES output transforms other than the three above, ACES 1.3, ACEScc and timelines other than DWG/DI are not converted yet: the picture is shown and measured as sent, and the label says "as sent, no Output Conversion" and why (#17).
- Performance with the Sender on has not been benchmarked on this release (#20); Stage 0 measured no change in Resolve's playback with the Sender's copy at UHD 23.976-60 fps. Checked after release (2026-11-16, #20): no change at UHD 50 fps with the Sender, or with the Sender and the app.

## [0.0.0] - 2026-11-15

Stage 0: colour and performance checks. Nothing here is the product yet; it is the evidence the product is built on.

### Added

- Throwaway probe Sender (`prototype/probe-sender/`): an OFX plugin that loads in Resolve 21.2 Studio, logs what Resolve tells it, dumps frames as float EXR, and copies UHD float frames out over CUDA into a shared-memory ring.
- Resolve test harness (`harness/`): builds a test project per Colour Setup, renders reference frames, reads the Colour Setup by script, drives playback and screenshots, clones the hand-placed Sender node to every project.
- Accuracy tool (`accuracy/`): compares the published colour maths with Resolve's own renders and reports each Colour Setup as exact or approximated.
- Stage 0 report (`docs/stage0-report.md`) and findings for every check (`docs/findings/`).
- ADR 0005: the Colour Setup comes from Resolve's scripting API and a manual override, not OFX.
- Glossary terms Viewer Frame and the Match Resolve luma mode.
- This changelog, Conventional Commits, Semantic Versioning and the findings convention (`CONTRIBUTING.md`).

### Changed

- ADR 0001: published maths is the Output Conversion method; the hidden branch is parked.
- ADR 0002: the Sender must never link OpenEXR or Imath.
- ADR 0003: "Resolve never waits" is proven at UHD float, 23.976 to 60 fps, on the CUDA path.
- ADR 0004: Resolve's waveform uses Rec.709 weights for P3; offered as a Match Resolve mode.
