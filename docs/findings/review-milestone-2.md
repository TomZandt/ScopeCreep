# Milestone 2 code review

A code review of the `milestone-2` integration branch found nine problems. Each was fixed with a test at the seam it belongs to (the pure layout seam, the settings seam or the Feed seam), except where noted. Nothing here was measured in Resolve.

| Finding | What was true | Pinned by |
|---|---|---|
| Label spilled out of its Panel | The label took as many lines as it needed and the display got the remainder, so at 1280 by 760 with 14 Panels a long label (8 or more lines) ran past its cell. Now the label keeps its first line and as many more as leave the display 80 logical pixels; the rest is clipped. The smallest Panel is 120 by 110 logical pixels. | `a_long_label_is_cut_off_rather_than_spilling_out_of_its_panel` |
| Saved borders unchecked | Any positive weights adding up to within 0.01 of 1 were accepted, however small the Panel, and never renormalised. Weights that leave a Panel under its minimum in the default 1280 by 760 window are now ignored, and the rest are scaled to add up to exactly 1. | `saved_positions_that_leave_a_panel_too_small_are_ignored` |
| Drag stuck with a menu open | A left Release was dropped while a menu was open, so a Loupe or border drag never ended. Release is now handled before the menu. This is in the window code and was checked by reading and a build, not by a test. | none (window code) |
| Luma ignored by 6 displays | Gamut/legal warning, ARRI False Colour, Highlight neutrals, both vectorscopes, Skin tone and the saturation heatmap used the weights from primaries whatever the luma waveform chose. The vectorscope label also always said "from primaries". CIE and Stops False Colour do not show Luma as the waveform does (CIE shows chromaticity; Stops uses scene-light weights adapted to D65) and are unchanged. | `every_display_that_shows_luma_follows_the_waveforms_luma_weights` |
| Feed thread busy when idle | Every millisecond it cloned the settings, built 14 labels and cloned the latest GPU frame twice. It now compares the Feed status and two version counters (menu choices; remembered state, which labels may show) and does the rest only on a change. | `the_version_goes_up_only_when_a_choice_changes` |
| Colour Waveform counted twice | It ran the same counting pass as the luma waveform into its own buffer. It now reads the luma waveform's counts and adds only its colour sums. The two vectorscopes bin the same frame at different zooms, so they have no counts in common and were left. | `colour_waveform_seam` (unchanged, still passing) |
| Non-atomic settings writes | Truncate then write under the settings lock, the same block three times, and a wheel tick at the zoom limit rewrote the file. One `save` (temporary file, then rename) is used everywhere, outside the lock, and a wheel tick that changes nothing remembers nothing. | `saving_replaces_the_file_whole_and_leaves_no_temporary_behind`, `a_wheel_tick_that_changes_no_zoom_remembers_nothing` |
| Text cache key too small | The shaped-text cache keyed on text, width and scale, but size, alignment and wrapping also change the shaping. The key now holds the whole style, and the float-equality line-height special case is an explicit multiple (1.4 for labels, 1.3 for scale numbers, 1.5 for the notice as in milestone 1). | none (window code) |
| Two Picture View labels | `Status::picture_label` copied `PictureView::label`, and three test benches and an example asserted on the copy. `PictureView::label_for` is the one source. | `feed_seam`, `output_conversion_seam`, `colour_setup_seam` |
