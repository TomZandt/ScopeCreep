# #204: the Window draws from a layout tree

What ticket #204 showed on 2026-11-20, at the pure layout seam (`app/tests/layout_tree.rs`, `app/tests/panel_grid.rs`, `app/tests/layouts_seam.rs`, `app/tests/min_window.rs`), headless. Nothing was checked at the app or in Resolve.

- The default layout is the old default grid run through the same conversion an old saved grid goes through (`layout_tree::tree_from_grid`): the first edge-to-edge cut found, side by side before stacked. At the default Panel area (1256 x 716, 12 px gap) the seven Panels are within 0.05 px of where the grid put them (the expected cells are worked out independently in the test).
- Because the tree has no shared columns or rows, dragging a gap moves only the two sides of that split. In the default layout the left and right halves split once at the top (so that border still runs the whole height), but the row borders on the left and right are now independent.
- A tab group needs one minimum Panel; a side-by-side split needs `gap + max(a / ratio, b / (1 - ratio))` across and the larger down, so a split holds its ratio and the Window's minimum is where every Panel is just at its minimum. For the default layout that Panel area is 313.5 x 518.9 (the grid's was 318 x 513.3), so the Window's minimum is 469 x 669 (was 469 x 645). One pixel less of area either way leaves a Panel under its minimum.
- Drag clamps use the same need, so a drag never leaves a Panel under its minimum and never changes who is next to whom (checked with extreme drags on five borders).
- The saved text is "layout 2" (a preorder of `split row|col ratio` and `leaf active Name[|Name]` lines). "layout 1" grids convert when they tile exactly and are a sequence of cuts; a pinwheel, holes, overlaps, a display missing from the layout, or rubbish give the default layout. Panels the layout names that no longer exist are dropped and the sibling takes the space. A ratio that would leave a Panel under its minimum in the reference window is moved to its limit; a layout that cannot fit at all is rubbish. Depth is capped at 24 and tab groups at 64.
- A layout that lacks a display the Window has gives the default layout (the grid used to place it in the first free cell); the displays offered are fixed until spec #196's Add list exists.
