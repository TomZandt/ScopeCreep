# Luma weights are derived from the Measured Space's primaries, not fixed to Rec.709

Many scope tools always use Rec.709 luma weights. scopecreep instead derives them mathematically from the Measured Space's primaries and white point (the Y row of its RGB-to-XYZ matrix). That reproduces the standards exactly where they exist (Rec.709: 0.2126/0.7152/0.0722; Rec.2020: 0.2627/0.6780/0.0593) and gives a consistent answer where no broadcast luma standard exists (P3-D65: 0.2290/0.6917/0.0793). The Scope label shows which weights are in use. Resolve's own waveform was measured in Stage 0 (ticket #8). It agrees for Rec.709 and for Rec.2020 and Rec.2100 (PQ and HLG, Rec.2020 weights), but uses **Rec.709 weights for P3-D65 and P3-DCI**, which differs from the primaries-derived P3 weights. It also computes luma on the encoded signal. The primaries-derived weights stay the default. The difference is offered as a **Match Resolve** mode rather than silently copied: use the weights Resolve's own waveform uses (Rec.709 weights for Rec.709, P3-D65 and P3-DCI; Rec.2020 weights for Rec.2020 and Rec.2100). The Scope label always shows which weights are in use.
